## 作者与原生几何

`Modeled` 使用明确的 `metric-basic-60-internal-v1` 轮廓：60° 牙侧、P/8 牙槽根部平底，常用 workshop 底孔可扩大基本小径。当前粗牙表为 M3/4/5/6/8/10/12/16；不是完整 ISO 公差等级认证。符号表达仍只保存意图并保留底孔，实体表达必须真实构造牙槽，旋向或有效深度变化必须重建。

螺旋作者来自解析圆柱上的精确 UV 直线，通过 .10 已有公共 `CreateAnalyticFace/LiftCurve/CreateWire/GuidedSweepPlan` 构造；没有采样折线作者。原生三维表示和扫掠报告公差分别检查；扫掠报告误差上限 1e-6 mm、工具拓扑公差上限 1e-5 mm。报告的算法误差不是全局认证误差界。

工具轴向裁剪到 [0, length]，有效长度限制 1–64 个螺距。通过源 bounds 只包围向前工具，不能据此推断制造孔深或拓扑身份。盲孔实际钻孔深度与有效螺纹深度独立。65 圈、非法尺寸/旋向/轮廓及预取消拒绝。

## 通孔回归与切削证明

应用首次使用原生 infinite-hole 底孔后再切牙，在 M5/M8/M12 等通孔上出现有有效拓扑却没有正确材料移除的结果。SDK-only `c5-history-1/2` 复现了该路径：更换布尔入口或延长工具均未解决；不能接受仅 `AlgorithmDone/IsValid`。

`c5-history-3` 将底孔和牙槽工具放在同一个作者 frame 中，以有限向前底孔工具切削，M8 LH/M12 RH 的材料移除与独立 screw-coordinate 积分相符，原生完整历史保留。应用接入该路径，并用独立工具交集复验每次切削量。小牙槽从大块体积相减放大数值误差，当前只在螺纹的三个积分见证上使用更严格一致精度；整个导入/显示缓存没有因本修复改成新的全局积分方式。

首轮“固定积分导致失败”的假设已被复验否定：锁定 .10 的 `InspectProperties` 本身已使用自适应积分。初次全局替换未解决通孔失败，已撤回。不能将该失败归结为已修复的积分缓存问题。

Cut 与 Common 修剪后的三维扫掠表示存在约 8e-6 mm³ 的体积差，进一步提高积分精度仍不能消除。切削比较明确使用独立 profile 消费者同样的 `max(1e-3 mm³, expected×1e-5)` 政策；应用独立 screw-coordinate 积分断言仍是 0.002 mm³，没有放宽。三个见证在钻孔坐标系中以 1e-11 量测，避免大平移/旋转造成几乎抵消的世界坐标面积贡献及自适应积分预算耗尽；整 BRep 和原生历史仍来自原作者空间，变换只用于体积量测。

通孔工具包围也在钻孔坐标系中对实际源形体取 bounds，避免旋转薄板的全局包围盒横向尺寸变成几十圈多余螺纹。bounds 继续只包围工具，不证明制造深度或选择身份。

## 原生计算隔离

生产 WPF 和 CLI 接入 `IsolatedMetricThreadExecutor`；孔、孔阵列重放、保存重验和实体制造证明均经过独立原生进程。每次作业复制精确源 BRep，校验输入/输出 SHA-256，并传输完整拓扑历史及专门制造证明。子进程使用无 executor 的内核，不回调父队列。

Windows kill-on-close Job 只拥有本次进程；取消或默认 90 秒超时关闭 Job、等待退出并清理本次临时目录，未产生结果时不提交文档。单资产 512 MiB、总输入 1 GiB、JSON 32 MiB；超预算明确拒绝。长且合法的 1–64P 作者仍可能触发时间预算，不能据此宣称所有合法作者都能成功或具有可接受速度。

## 制造与保存

实体孔采用专门证明：先独立量测完整底孔，再重放牙槽 Boolean；当前整实体及所有拓扑槽必须与重放相符。被选牙面或残余底孔壁必须来自原生工具/底孔关系，不按邻近距离、面积或遍历位置重绑。保存完整当前作者规格、底孔尺寸及原生证明面集合。普通底孔证明不能冒充实体牙型证明。

直接实体孔、孔阵列的有效缓存保存/重开要求完整原生作者重放；缺验证器或伪造结果拒绝。实体孔生产选择器、结构化作者、参数和交换报告均已接入，STEP 含牙型但不能保留原生特征/旋向意图。当前格式 document48/features41/drawings14/sketches18/history4；features40 和 drawings13 夹带实体语义拒绝，旧符号文件分别迁移。drawings12→13 的历史符号迁移保持固定。
