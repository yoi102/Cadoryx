## 已核对的实现与公开能力

应用 [CreatePresentation](../Cadoryx.Rendering.Occt/OcctViewport.cs) 在正常来源样式路径调用 `OcctViewer.Display(XdeLabel)`，随后设置实例位姿、显示模式和选择类型。精确选择/关联基准绑定及整体选中高亮走独立 Shape 路径，不能把这些入口改成失去拓扑的显示对象。

SDK `.11` 的手写 `Visualization/Presentations.cpp` 对每次 XDE Display 创建新的 `AIS_ColoredShape`、读取来源样式并提交 context。`Visualization/Context.hxx` 保存逐 presentation 注册表；`Selection.cpp` 通过检测/选中 AIS 对象找回 presentation ID，再返回实际所选拓扑。这一身份链必须保留。

独立 NuGet 程序 [ViewerCapabilityProbe](../tools/ViewerCapabilityProbe/Program.cs) 已对冻结 `.11` 的 13 个公共 SDK 程序集完成只读清点：4,483 个导出类型中存在 `AISConnectedInteractive`、`AISMultipleConnectedInteractive` 和 `AISInteractiveContext`，其 Connect/Display 为公开能力；高层 `OcctViewer` 的公开 Display 接受 Shape、XdeLabel 或 XdeOccurrence，内部 ViewerHandle 不公开。当前高层对象的公开方法没有将低层 connected AIS 加入其 presentation 注册表的组合入口。

证据 `artifacts/a5-viewer-capability-2/result.json` 只证明实际公共签名和 DLL 身份，不是渲染、选择或性能 PASS。第一次清点只查高层所在程序集，仅得到两个高层类型，原输出保留；第二次遍历全部 13 程序集，并统一类型名中的下划线，不能把第一次范围不足解释成底层没有 connected API。

补充清点已覆盖全部公共程序集中的来源/窗口返回方法，而不只检查构造函数：26个相关类型包括实际名称 `WNTWindow`/`WNTWClass`。它们存在，但 `WNTWindow` 与 `AISShape` 无公开构造，`V3dView` 无公开 `SetWindow`，`AISColoredShape` 的公开构造仅接受已有低层 `AISShape`；低层包装类的托管基类为 `System.Object`，不能假设它们可直接互相转换。全程序集来源/窗口返回方法没有静态工厂；查询、Clone或依赖已有对象的Connect不构成从应用拥有的Shape/XDE和HWND直接创建该场景的证明。该清点仍不是原生消费者或缺失整个底层能力的声明。证据见 `artifacts/a5-viewer-capability-verification-2.json`；旧只查高层及后续三轮清点输出均保留。

因此先在独立原生OCCT消费者中验证connected来源样式、选择及生命周期，再确定应用高层的最小安全拥有关系适配；不借用私有托管句柄或绕过注册表。在真实消费者通过前，不直接把connected类接入生产视口。固定性能目标、选择与来源样式门禁不变。
