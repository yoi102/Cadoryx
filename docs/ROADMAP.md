- IO-01：结构节使用 MessagePack 3.1.8，稳定数值 Key、白名单 DTO、UntrustedData 安全选项；禁止 Typeless。JSON 仅作清单及 v1 结构节兼容读取。

## 2. 实施顺序

采用能够从 UI 操作到文件保存的纵向阶段，每阶段都有实际行为和失败路径。先验证窗口/内核边界，再扩大建模范围。

### M0：领域与会话基础

实施：

- 新建 `Cadoryx.Db`，实现强类型 ID、双精度数值、单位、公差、不可变快照、Part/Assembly/Slot/Body/AssetRef 与领域验证。
- 新建 Kernel.Abstractions；先定义当前阶段确实使用的资产、能力、交换契约，不创建无行为的万能内核接口。
- 新建 Editor 项目，Commands、Session、Selection 初期可放同项目的不同命名空间；长出真实职责后再独立 Commands 程序集。
- 显式文档工厂/作用域；Workspace、CadDocumentViewModel、多文档标签、活动文档命令路由。
- 模型树/属性从文档快照投影；移除示例节点；没有能力时禁用命令并给出恰当原因。

验收：新建两个文档、切换和关闭不串数据；重复定义/循环装配/非法数值被拒绝；相同子装配的两条实例路径正确区分；ViewModels/Db 不引用 OcctSharp 或 WPF 句柄。

### M1：真实内核、导入与视口

实施：

- 创建 Kernel.Occt、Rendering/Rendering.Occt，锁定经过消费验证的 NuGet 版本，配置 win-x64。
- 在现有 WPF View 接入 HwndHost，完成对话框 airspace 处理、独立视图工具行与生命周期。
- STEP/IGES 默认走 XDE，保留受支持的装配、位姿、名称、颜色与单位，生成 Cadoryx ID 和来源映射。
- UI 独立显示上下文；完整模型导航、FitAll、标准视图、实例选择、树与属性同步。
- 文件读取在内核队列准备；活动文档的版本/关闭状态阻止旧结果提交。

验收：已知尺寸/单位的 STEP 与 IGES；嵌套重复装配位置正确；切换文档不丢相机；主窗口对话框可见可操作；Viewer 创建/销毁不泄漏；干净发布目录可运行。

阶段完成时产品是可用的模型查看/检查程序，尚不宣称完整 CAD 建模。

### M2：首个完整直接编辑闭环

实施：

- Primitive Box/Cylinder、重命名、持久显隐、颜色/材料修改、实例刚体移动。
- Fuse/Cut/Common 和明确的输出数量/空结果策略。
- 工具参数、预览、确认/取消，文档两阶段提交、失败回滚。
- 已提交精确资产与文档状态历史；撤销/重做、保存点和差量场景同步。
- 在 M3 完成前，为阶段演示可采用明确标为开发用途的临时资产仓，不能把未持久化资产假装已保存。

验收：新建 Box → Cylinder → Cut → 撤销 → 重做；确认前不脏；取消无残留；修改共享零件更新全部实例；失败不半提交；撤销/重做不再次运行内核。

### M3：原生文档与可靠文件操作

实施：

- `.cadoryx` ZIP、manifest、分节 DTO、资产目录、hash 与逐节迁移。
- 只读取设置/摘要；原子保存、另存为、保存点、恢复快照。
- 当前特征图所有可达源资产完整嵌入；不要只存屏幕上可见的最新结果。
- 打开错误/未知版本/缺失能力边界；STEP/IGES/STL 导出和信息损失报告。

验收：关闭再打开后稳定 ID、装配结构、BRep、材料和命名视图正确；破损包和未来必需节不静默加载；保存中断保留旧文件；异步保存时新编辑仍标脏；无内核初始化的 settings 读取。

M2 + M3 是第一份“能建模、能撤销、能保存恢复”的交付基线。不要先把 Ribbon 上的几十个建模按钮全部做成占位，再补这条闭环。

### M4：草图驱动参数化零件

实施：

- 基准面、草图线/圆/圆弧、捕捉、二维编辑及轮廓合法性。
- Extrude/Revolve 与类型化参数、依赖图、增量重算、抑制/恢复语义。
- 先用数值驱动草图形成可靠轮廓；通用约束求解器单独评估并接入，不能和“有二维曲线”混为一项。
- 定义可支持的拓扑命名范围，接入语义输出与算法历史；圆角/倒角通过该门禁后启用。

验收：修改拉伸距离能重算后继布尔；循环依赖拒绝；失败保留旧状态；拓扑变更后歧义边不自动误选；保存恢复参数和支持范围内的引用；约束求解自由度/冲突诊断与实际几何一致。

### M5：装配编辑与约束

实施：

- 插入、替换、删除实例、使独立、重挂父级、可复用子装配编辑。
- 明确“编辑共享定义”和“仅改当前实例”的上下文。
- 装配约束模型：ConstraintId、参与实例路径、基准/拓扑引用、参数、状态；预留 Fixed/Coincident/Concentric/Distance/Angle 等。
- 先做固定/刚体位置管理；机械配合约束求解独立设计和评估，不视为 OCCT Shape 变换自然附带的功能。
- 外部零件链接与按版本更新独立于嵌入装配；冲突、缺失文件和更新结果可追溯。

验收：重复嵌套子装配选中与编辑正确；重挂父级保世界位置；定义共享影响可解释；不允许环；缺失拓扑的配合明确失效；撤销保持身份和引用完整。

### M6：大型模型、交付与扩展

实施：

- 大型模型的资产/历史预算、实例复用、树虚拟化、按需几何加载和自适应网格显示。
- 基于实际测量决定多内核 worker、进程隔离或视口合成路线。
- 多视口、测量/剖切、更多局部建模、工程标注和命令行逐项纵向交付。
- 可复现打包、版本兼容、恢复、DPI/远程桌面和长时间运行验收。

验收样本和性能预算需要用真实模型确定。建议建三档固定样本：小型精确零件、重复实例装配、大型导入装配；记录文件大小、定义数、实例数、面数、硬件、导入耗时、首帧时间、交互延迟、峰值内存和历史占用，不在未测量时保证“百万面 60fps”。

## 3. 测试组织

| 测试层 | 主要验证 | 环境 |
|---|---|---|
| Db 单元测试 | ID/引用/环、变换组合、单位、公差、不可变快照 | 不需 OCCT/WPF |
| Commands/Editor | 过期结果、失败原子性、保存点、历史分支、预览取消 | 可控 fake kernel + 部分真实内核 |
| IO | 分节迁移、往返、hash、可达资产、未来版本、原子替换失败 | 临时目录，逐版本小样本 |
| Kernel.Occt 集成 | 单位、BRep 合法性、布尔、XDE 装配元数据、所有权 | 对应 NuGet 与 win-x64 原生运行时 |
| Rendering/WPF | 选取映射、DPI、airspace、浮动重建、关闭释放 | Windows 桌面与 OpenGL |
| 发布消费者 | 无参考源码/PATH 的恢复、运行和导入 | 干净目录/目标 Windows 环境 |

几何测试优先断言体积、包围盒、距离、公差内位置与拓扑合法性；不把容易随内核变化的遍历顺序当成稳定功能要求。持久资产 hash 用于字节完整性，不作为两个独立重建结果几何相等的唯一判据。

按变化影响运行检查。文档调整做链接/结构/事实核查；领域变动做领域测试；Viewer 变动必须真实 Windows 验收。编译通过不能替代原生生命周期或视觉验证。
