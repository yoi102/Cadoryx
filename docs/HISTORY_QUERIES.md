# H2-C1：历史诊断查询与窗口

历史诊断查询保存一份源 Box 面／边语义引用和一个目标 `FeatureId`。它是只读诊断配置，不是建模输入。查询不保存临时拓扑索引、原生句柄或上次解析结果；每次打开窗口或点击“分析当前文档”时，从当前不可变快照重新规划路径并调用 `ITopologyHistoryResolver`。`Resolved` 只表示此刻的唯一历史结果，不能直接作为 H2-C2 的持久跨特征建模引用。

主窗口“局部特征”页签提供“历史诊断”入口，打开带 Owner 的 `mah:MetroWindow`。先在局部特征窗口保存 Box 面／边源引用，再在诊断窗口新建查询、明确选择源并选目标特征。窗口展示每段特征、输入槽位、已验证／停止／未处理状态，以及总状态、诊断代码、完成段数、停止特征和成功时的临时目标编号。源引用删除后，查询中的复制品仍在，故失效查询可重新打开查看 `Missing`／`Stale`；选新源必须点击“重新选择源”并保存，不会自动重绑定。

保存、删除与显式重选都经过文档命令和精确撤销／重做。查询名与源／目标 ID 随不可变文档走；文档变化会清除旧窗口结果，取消在途诊断。每次异步返回还检查文档和 `StateId`、查询 ID 与窗口运行序号，旧结果不能覆盖新状态。诊断期间通过 `DocumentCapture` 与 `TopologyHistoryInspection` 保持资产租约，取消和关闭后释放。原生单次调用内部仍不能即时中断。

`.cadoryx` 写出版本为 0.4.6：原八节之外增加必需的 `history-queries` v1 MessagePack 节，`document` 升到 v6，新增 `cadoryx.history-queries.1` 能力。DTO 使用稳定数值 Key 和同一个安全反序列化配置，完整嵌入源语义引用；旧 document v5 经显式规则添入空查询节，早期版本沿已有规则继续迁移。损坏节拒绝加载，旧应用不能静默丢弃查询。查询无独立资产，BRep 仍按原有资产目录管理。

当前只接受已有的 Box 语义面／边引用。删除源特征或目标特征后保留查询及身份供诊断，不会推断替代路径；生成面／边重新选择、通用拓扑命名和跨特征建模引用留给 H2-C2/T3。OcctSharp 的固定 .2 NuGet 已提供本阶段需要的 `TraceAsync` 底层证据；本阶段没有发现新封装缺口，也没有变更原生 ABI。
