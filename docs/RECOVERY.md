# 自动快照与异常退出恢复

M3-R 的实际实现，更新于 2026-09-12。恢复快照复用现有 `.cadoryx` 文件格式：ZIP、JSON 清单、MessagePack v2 结构节和精确 BRep/XDE 资产。

## 用户行为

- 每 30 秒尝试捕获所有脏文档。相同 StateId 和原路径不重复写入；上次任务未完成时合并定时触发。
- 下次启动发现已退出进程的快照时，自动打开“文档恢复”。也可从“文件 → 文档恢复”进入，刷新、恢复副本、丢弃快照或稍后处理。
- 恢复创建一个未保存、保持脏状态的新标签。原路径只作来源说明；保存时需要选择位置，恢复过程不写原文件。
- 通常保留最近两份完整快照。最新快照损坏时尝试前一份，并在消息面板报告；全部损坏时报告错误并保留文件。
- 正常保存会协调清理已保存状态的恢复记录；保存期间产生新编辑时，保留该脏状态的保护。正常关闭或确认放弃文档会清理对应会话记录。
- 关闭恢复窗口或选择“稍后处理”不丢弃快照。“丢弃快照”需要界面确认，不影响原文件。

## 分层与数据

| 层 | 实现 | 职责 |
|---|---|---|
| Kernel.Abstractions | RecoveryContracts | RecoveryKey、RecoveryEntry、RecoveryDocument、IRecoveryStore |
| IO | CadRecoveryStore | 快照持久化、进程占用锁、扫描、校验、回退和删除 |
| Editor | DocumentRecoveryService | 捕获快照和资产租约、合并定时任务、保存/关闭协调 |
| Editor | DocumentSession / Workspace | 独立 SessionId、原路径与脏状态的原子捕获、恢复会话创建 |
| ViewModels | RecoveryCenterViewModel / MainWindowViewModel | 列表命令、工作区接入、持久副本交接和错误消息 |
| WPF | RecoveryHost / RecoveryDialogService / RecoveryWindow | 30 秒定时器、非模态 owner 窗口、三种语言资源 |

`SessionId` 是本次打开的身份；`DocumentId` 是持久业务身份，同一文档的多个副本不能共用清理键。`RecoveryKey=(RunId, SessionId)` 定位记录。`DocumentCapture` 在会话锁内一次性捕获 Snapshot、IsDirty、FilePath，并持有全部可达资产租约，写入期间继续编辑或释放历史不会使快照缺少资产。

默认位置为 `%LOCALAPPDATA%\Cadoryx\Recovery`：

```text
Recovery/
  <RunId>/
    owner.lock
    <SessionId>/
      <RevisionId>.cadoryx
      <RevisionId>.json
      inactive                 # 清理尚未完成时留下的关闭标记
```

目录和文件身份均为非空 GUID。元数据 version=1，包含 Sequence、DocumentId、StateId、Name、OriginalPath、CapturedAt。Sequence 单调增加，用于选择和保留版本；时间用于显示，系统时钟回拨不会使旧状态取代新状态。

## 写入、交接与关闭顺序

1. 进程首次写入时创建自己的运行目录，以 `FileShare.None` 持有 `owner.lock`。目录创建失败只报告恢复错误，不阻止主窗口启动。
2. 在后台写完整 `.cadoryx`，复用现有验证和原子发布；再写元数据临时文件并 Flush，最后改名发布 JSON。没有已发布元数据的负载不参与恢复。
3. 新快照发布后才删除旧版本。保留两份；清理失败可能暂时保留更多文件，后续写入重试。
4. 扫描只能取得已退出进程的锁。恢复和丢弃持有来源进程锁，其他 Cadoryx 进程不能同时接管该来源。
5. 恢复时先加载并验证来源，创建未保存会话，**在当前进程写好完整快照**，再挂入停靠区，最后退休旧记录。新副本写入失败时保留来源；交接中断可能留下两个可恢复副本，不能提前删除唯一副本。
6. 关闭先移除会话跟踪，等待正在写入的快照结束，再发布 `inactive` 标记和清理文件，最后释放会话。中途终止时标记阻止已确认关闭的文档重新出现。
7. 文件清完后移除空会话目录；运行结束或来源交接完成时尝试移除空运行目录。所有删除只针对计算得到的恢复目录，不递归删除未知子目录；竞争进程持锁时保留目录。

每个文档的写入失败独立报告，其他文档继续保护；后台快照不会修改 FilePath、保存点、Generation 或撤销历史。

## 限额与边界

- 扫描每次最多 1000 个运行目录、每运行 1000 个会话、每会话 100 份元数据；单份元数据最多 64 KiB。拒绝恢复根目录内部的符号链接/目录联接、非法 GUID 和身份不匹配。原路径不用于定位负载。
- 快照沿用原生文档的 ZIP、长度、SHA-256、版本与资产限额。当前实现是完整快照，每份包含可达源资产；尚未提供跨快照的磁盘去重或总磁盘预算。
- 30 秒是触发间隔，不是“最多丢失 30 秒”的保证。后台排队、磁盘写入、窗口线程繁忙或写入失败会拉长间隔；只能恢复最近成功完成的快照。
- 保存当前已提交业务状态与特征设计历史，不保存内存撤销/重做栈、未确认工具预览、运行中的原生计算或窗口布局。
- 元数据完全损坏时可能只有诊断，没有可操作列表行；文件保留供排查。未知文件、失败产生的孤立目录不自动递归清除。达到扫描限额时会报告诊断。
- 自动快照不等于备份。当前已覆盖受控进程强制终止；断电、实际磁盘满、系统崩溃和网络盘行为仍需专项故障矩阵。

## 可重复验证

```powershell
./scripts/verify.ps1 -PublishSmoke -RecoverySmoke
```

执行锁定依赖恢复、Release 构建、当前 78 项测试、发布目录 WPF 冒烟，以及两进程恢复冒烟。恢复测试让生产 30 秒定时器写入一个真实 OCCT 模型，然后仅强制终止脚本启动的测试进程；重启后通过恢复窗口的命令恢复，核对文档/状态/体/资产身份、图层/材料/实例变换、原文件 SHA-256、未保存状态、原生视口、另存为、关闭清理和资产归零。

`--smoke`、`--recovery-seed`、`--recovery-verify` 均使用指定输出目录下的隔离恢复根，不读取或丢弃用户正常工作的恢复数据。日志、预期身份、模型和截图保留在 `artifacts`，具体本次路径见 [ROADMAP 验证记录](ROADMAP.md#5-本轮验证记录)。WPF 外壳截图不包含 HwndHost 的 OpenGL 图像，需同时查看 `restored-viewport.png`。
