# A/F 主窗口新建与打开的失败回滚

2026-10-13，source1081。普通新建、原生打开及交换打开在停靠窗口或文档集合通知失败时，现在释放尚未接受的候选会话；激活失败恢复原活动文档。新建的异常通过既有工作区日志与状态反馈，空工作区的建模/草图入口等待新建结束再继续。[独立审计](../capability-evidence/diagnostics/af1081-attachment/verification.json)记录真实旧失败与当前托管结果。

旧 `New()` 直接调用同步 `Attach(workspace.Create(...))`，失败会向调用方抛出异常且没有关闭后台候选。两种打开入口会报告异常，但同样没有关闭已经加入工作区的会话。`Attach` 把 `Documents.Add` 放在回滚保护外；激活后失败时又用 `Documents.LastOrDefault()` 恢复，可能切换到与操作前不同的文档。这些路径违反失败不留下半提交状态的要求。

修正给普通新建/打开统一增加候选所有权守卫，失败时调用 `workspace.CloseAsync`；原生读取的 loaded 租约仍按既有作用域释放。集合加入也进入 `Attach` 的回滚保护，恢复仍有效的原活动文档（包括原来没有活动文档的状态）。工具工作区和恢复入口已自带候选关闭逻辑，继续使用它们的原路径。没有更改作者、几何、历史、身份规则或 SDK 封装。

15 个新增检查从实际生产 `NewCommand`、`StartToolCommand`、`NewSketchCommand` 和 `OpenPathAsync` 进入：两文档、原活动不是最后一项时，覆盖新建/原生打开/交换入口的集合通知、停靠打开和激活故障；空工作区再覆盖显式/隐式新建。检查原文档快照与历史、活动状态、后台会话集合、加载资产释放、错误反馈、忙状态及下一次成功重试。原生文件用实际存储保存/读取带扩展资产的空作者；交换入口只用读取该作者的 importer 夹具，证明分派和生命周期，不宣称真实 STEP 导入已验。
