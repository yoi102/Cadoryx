# 零件归属、文档资源与实例位置

M2-I 的实现说明，更新于 2026-09-12。入口为主页工具栏或“文件 → 文档资源”；模型树和右侧属性、建模参数面板配合完成编辑。

## 使用流程

1. 在“文档资源 → 零件”输入名称并新增零件。新零件挂在根装配下，并自动成为当前建模目标；也可以选择已有零件设为目标或重命名其定义。
2. 在图层页新增/修改名称、颜色、可见性和锁定状态。在材料页维护名称及密度，界面单位为 kg/m³。
3. 建模参数的“创建归属”中选择目标零件、图层和材料，计算预览后确认。初始空文档在第一次确认实体时创建零件；更改任一归属选择会取消旧预览。
4. 选择模型树中的实体，在属性面板修改图层、外观和材料。“不指定材料”清除材料选择，点击“应用属性”后生效。质量按精确体积和密度计算，单位 kg。
5. 选择零件或装配实例节点，在“实例位置”编辑父坐标系下的平移 mm、旋转轴和角度 °，再应用。改变位置不重建 BRep。

资源窗口每次“新增 / 应用 / 删除”都是一个立即生效的文档命令，关闭窗口后可撤销/重做。“关闭”不会撤回已经应用的修改；仅输入但未应用的字段不改变文档。资源窗口绑定打开它的文档，模态期间不会串到其他标签。

## 共享定义与实例

`PartDefinition.Id` 表示共享零件定义，`OccurrencePath` 表示具体展开路径。新建实体、实体属性和特征参数修改作用于定义，会在该定义的所有实例中显示。模型树点击零件节点可以确定建模目标；当实例名称与定义名称不同时，节点显示 `实例名称 [定义名称]`。

实例移动通过完整路径解析所属装配与 `ComponentSlot`，保存局部 `RigidTransform3d`。世界位置由父变换乘局部变换得到，不把界面数值误当成世界坐标。平移编辑保留原有四元数，避免一次不涉及旋转的操作改变导入模型的朝向。

当前支持根级实例，以及父装配只有一个展开实例的嵌套节点。如果父装配被复用，子槽位本身也是共享定义数据；此时面板说明原因并禁止独立移动该子路径，命令层同样拒绝。可以选择更高层的父实例移动。复制子装配定义、使实例独立及完整装配编辑留在 M5，当前不会悄悄复制定义或连带移动其他展开路径。

## 资源规则

| 行为 | 规则 |
|---|---|
| 创建体 | 显式目标 PartId、LayerId、MaterialId 进入候选和最终快照；省略目标且存在多个零件时命令拒绝执行 |
| 创建外观 | 新体默认 ByLayer；图层颜色修改影响所有按图层着色的实例，显式体颜色不随图层颜色变化 |
| 图层锁定 | 禁止在锁定图层创建体、修改其体属性、布尔和受影响特征闭包重算；资源管理仍可解锁 |
| 图层可见性 | 更新托管场景并刷新原生视口，所有共享实例一致 |
| 图层删除 | 至少保留一个图层；实体或保留特征输出存在引用时拒绝删除 |
| 材料删除 | 检查实体和保留特征输出引用；清除引用后才可删除 |
| 材料密度 | 必须是有限正数；界面 kg/m³ 转换为已有协议的 kg/mm³，除以 10⁹ |
| 名称 | 图层/材料名称不能与同类资源重名，忽略首尾空格和大小写；业务身份始终由 ID 区分 |
| 空结果 | 布尔/重算结果暂时无实体时，仍保留输出名称、图层、外观、显隐和材料，以便之后恢复 |

引用数是实体引用与特征输出引用之和，一个可见实体可能对应两条引用。内存撤销历史持有完整旧快照，不需要为了历史引用禁止删除当前已不使用的资源。

## 代码入口

| 模块 | 实现 |
|---|---|
| Db | `OccurrencePlacement.Resolve` 校验路径，定位 owner/slot 并计算父装配展开次数 |
| Commands | `ResourceCommands` 管理零件/图层/材料；`AddBodyCommand` 验证归属后才调用内核 |
| Commands | `DocumentEdits.SetBodyProperties` 原子更新体和保留输出属性；`MoveOccurrence` 只修改允许独立移动的槽位 |
| Commands | `RecomputeCommand` 在计算前检查依赖闭包内的锁定图层；布尔保留被消费源体的输出属性 |
| Editor | `SelectionService` 同时支持实体选中与只有实例路径的选中，空零件也能编辑位置 |
| ViewModels | `DocumentResourcesViewModel`、`InstancePlacementViewModel`，以及文档的创建归属默认值 |
| WPF | `DocumentResourcesDialog`、`InstancePlacementView`，共用弹窗风格和文档级 UI 生命周期 |

图层、材料、体引用、位姿和输出元数据均使用已有 MessagePack v2 字段，本阶段没有新增格式编号或改变字段 Key。保存重开和恢复快照复用相同协议。

## 弹窗与生命周期

M2-I 原验收使用独立 `mah:MetroWindow`。当前工作区的文档资源、恢复、导出选项、应用设置和保存确认已改为 `DialogHost` 内容，消息/进度/退出确认也使用此承载方式；系统文件选择器保留标准 owner 窗口。M3-V 已按当前 Popup 内容完成回归，诊断通过 DialogSession.Content 获取实际显示内容。以后新增独立应用窗口继续遵循 `mah:MetroWindow` 风格要求。

关闭文档通过 `CadDocumentViewModel.Detaching` 显式通知原生视图释放，再释放会话资产；不依赖 WPF 延迟发生的 `Unloaded`。迟到的 Loaded/Ready 不得为已关闭文档重建视口。这条顺序在本阶段扩展恢复验收时补齐。

## 验收与边界

```powershell
./scripts/verify.ps1 -PublishSmoke -RecoverySmoke
```

当前共 78 项测试，其中新增 18 项覆盖创建目标、共享实例预览、无效目标前置拒绝、图层与材料引用、密度换算、锁定与空结果、精确撤销、局部位姿、共享父级拒绝，以及保存重开/恢复保真。

真实 WPF 冒烟通过菜单命令打开模态资源窗口，输入名称和密度，创建新零件/图层/材料，再验证建模归属、位置输入绑定、图层显隐、撤销与保存。中/英/日资源页、Metro 弹窗、主窗口和原生视口截图保留在 artifacts。异常退出测试额外核对图层、材料、体属性和实例变换。最终证据路径在 [ROADMAP](ROADMAP.md)。

完整装配独立化、资源批量替换、外部材料库、纹理/PBR 材质、材料交换元数据及大型文档性能不在本阶段完成范围。
