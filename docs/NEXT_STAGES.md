## M14：先解决用户可感知的等待

生产 `OpenPathAsync → 独立 STEP 工作进程 → 临时 .cadoryx → 主进程延迟资产 → 首个非空画面 → 完整场景` 的端到端计时已建立，最终发布版两轮证据见 [M14](M14_LARGE_MODEL_OPEN.md)。M12 的 81.04 秒只代表直接内核与磁盘资产基准，不能代替点击打开耗时；M12 分段的约 38 秒原生读取、约 41 秒逐定义转换和 M14 较早的约 7.5 秒原生 Display 也不能当成稳定常数。下一步要先固定系统负载/缓存条件并重复测量，再独立验证交换读取、精确转换及带源样式的逐实例显示方案；同时复核等待提示、进度、取消、选择反馈与错误定位，**保留 XDE 继承面色、精确 BRep、实例身份与取消/清理语义**。固定样本 `MiniPC3.step` 的哈希和两轮双视口基准见 [M12](M12_INTERACTION_AND_PERFORMANCE.md)。

完成标准：从同一发布版、同一文件哈希和记录硬件/缓存条件的重复运行报告点击打开总时长、首画面与完整画面；完整场景提交以 M12 的 9.26 秒作基线，目标是至少降低 30%，若原生限制导致目标不可达则保留分段证据和明确的 OcctSharp 能力缺口，不以颜色或装配信息丢失换速度。双视口旋转/选择、打开取消、关闭与资产释放不退化。任何需要新增 OcctSharp 接口的优化先对**实际锁定包**做独立消费探针，再决定上游封装。

## M15：把精确 CAD 操作的边界推向复杂模型

草图先补当前受限三次样条之外的控制点/结点编辑、真正的曲线交点和相切/曲率约束，再接孔岛与关联重算；复杂拓扑面的手柄按几何类型逐项提供，不用屏幕近似值写入文档。特征树的抑制/回滚位置目前仍是数据设计，需明确输出直通、阻断和重算规则后才接 UI。装配补更广的奇异、欠约束和多解诊断，以及真实厂商 STEP/XDE 的基准与来源依赖检查。跨重算拓扑身份只能对有可证明历史和唯一目标的路径提供持续绑定；分裂、合并或多路径仍要求重选，**不按遍历序号猜测**。全局通用拓扑命名是研究性能力，不作为其它可用功能的隐性前置。

完成标准：真实样本展示编辑→候选预览→确认/取消→撤销/重做→保存/重开→恢复的闭环；旧文档迁移、错误资产/修订、共享定义、多实例和冲突装配均有拒绝或诊断证据。新的结构字段先定义稳定 ID、MessagePack 版本及迁移，再提升写出版本。不能把局部数值解宣称为全局唯一解。

## M16：让工程资料和自动化可用于交付

工程图补局部放大、剖面线、ISO/GB/ASME 可选模板、尺寸/公差与图框表达；物理打印从 M17 环境门禁取证。交换以多厂商固定 STEP/IGES/STL 样本核对装配层级、单位、面色、PMI 与丢失项，IGES 曲面/实体语义不可保留时明确报出。外部材料库、纹理和 PBR 材质需要独立的持久化与交换契约，不把现有简单颜色误称为完整材质系统。命令行和 AI Agent 扩展到用户常用的草图、装配、图纸操作，但每个写操作继续要求精确文档/状态/对象身份、预览与撤销；不允许模型文本直接调用任意 CAD API。补文件对话框、Ctrl+V、长对话、取消、视觉附件与不同 DPI 的人工使用验收。

完成标准：真实零件和装配的关联图纸经模型修改后正确刷新，PDF 和打印预览可读；交换报告逐项记录保留与损失；Agent 工具返回的成功与文档实际状态一致，过期/歧义输入不改模型。将外部模型服务可用性、响应质量和本地工具安全分别报告。

## M17：最后取得真实交付证据

使用 M13 已固定的 MSI 和 SHA-256，在**未安装开发 SDK/本地 OcctSharp 包**的 Windows x64 机器验证安装、首次启动、STEP/IGES/STL、文档保存/恢复、升级和卸载。再做两台不同 DPI 显示器之间的停靠/浮动、RDP 断线重连、多 GPU/驱动、数小时大模型交互、物理打印机输出与资源趋势。真实磁盘满、断电及网络盘与既有故障注入分开记录。签名、外部 CI 和公开发布各自保留独立结果；公开发布前需有相应发行授权与可核对的最终包。

这些环境设备和外部服务未在当前本机证据中出现时，只能标为“未验收”。M14–M16 可在同一开发机实施；M17 的实机矩阵可提前准备样本与脚本，但不能由模拟 PATH、短时冒烟或本机 MSI 安装自动代替。
