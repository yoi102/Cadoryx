# M10–M11 与交付验收规划

本页保留 2026-09-27 确认的阶段验收契约。M10 的实际实现、范围与证据见 [M10 装配](M10_ASSEMBLY.md)；下文的 M10 数据契约是设计基线，不能据此推断所有极端场景均已验收。M11 的有界实现见 [M11 工程图](M11_TECHNICAL_DRAWINGS.md)，M13 本机安装器已实现，外部环境交付验收仍待实施。当前结论见 [STATUS](STATUS.md)。

## M10：完整装配

目标：用户从实际 BRep 选择几何基准，建立能包含闭环的装配关系；系统计算位姿并报告剩余自由度、冗余和矛盾；来源文档的依赖可检查并安全刷新。现有 M5 有固定、点、轴、平面关系及保守有向调整，但其拓扑引用仅作过期诊断，不能由真实面/边生成基准；遇未满足闭环或多驱动会拒绝。M10 需真正替换这一能力边界，不能只放宽现有拒绝条件。

| 工作面 | 实施内容 | 必须满足的边界 |
|---|---|---|
| 几何基准 | 在当前精确 BRep 上拾取平面、圆柱面、圆边，提取点、法向/轴、圆心与半径；把局部基准与实例位姿分开 | 只接受能由解析曲面/曲线证明的基准；自由曲面、退化、歧义、分裂和错误实体类型需明确报错，不按面序号猜测重绑定 |
| 闭环配合 | 固定、点重合/距离、平行/同轴、角度、平面贴合在同一连通图上求解；允许一个移动实例受多个关系及闭环约束 | 将所有位姿放入隔离候选，一次性验证全图残差和限额；超时、未收敛、冲突、锁定及过期结果均不提交 |
| 自由度诊断 | 以求解点的几何约束 Jacobian 计算局部秩、零空间、连通分量和固定参考 | 报告整体漂移、局部自由度及冗余；奇异/近奇异结果标为不确定，不把单个找到的解宣称唯一，也不把未收敛宣称无解 |
| 跨文档依赖 | 来源身份、零件身份、版本/状态、哈希和冻结快照组成显式依赖图；检查缺失、变化、环和多级刷新顺序 | 普通打开/渲染不隐式改动来源；刷新预演先检查全链和本地冲突，提交单个目标文档为一次可撤销事务；缺失来源继续使用冻结形体 |
| 用户操作 | 视口/树中选实例和面/边；关系编辑器展示选中的真实基准、目标值、残差、自由度及修复提示；预览/确认/取消 | 同一关系的来源变旧时要求显式重选；反馈定位到具体实例/关系；多实例同源零件不能误操作共享定义 |

### 数据与命令契约

- `AssemblyDatumReference`（拟新增）应保存文档 ID、实例路径、定义/Body/Feature ID、资产 ID、结果修订、原始 BRep 指纹、拓扑种类和精确绑定证据，以及提取时的局部几何参数。局部参数只作缓存；使用前必须重新从匹配的原始 BRep 验证。不同实例可以引用同一零件资产，但位姿由各自 `OccurrencePath` 决定。不能仅靠拓扑遍历序号跨重算复用。
- `AssemblyConstraint` 保留稳定关系 ID 和现有关系语义；为两端增加可选几何基准引用，并为旧手输基准保留明确来源标记。迁移旧关系时不得伪造真实 BRep 证据。关系目标、公差、启用状态及精确依赖均进入文档快照。
- `AssemblySolveReport` 扩展为逐连通分量、逐关系残差、自由度/秩/冗余、失败原因和候选位姿。诊断报告可重算，不可代替已提交的装配约束。求解器只产出候选；`ICadDocumentCommand` 在会话代数和所有来源修订核对后一次提交，并复用现有 Undo/Redo、保存点及资产租约。
- `ExternalDocumentDependency`（拟新增）以来源 `DocumentId + PartId + StateId + SHA-256` 及规范化路径、冻结快照身份建立边。解析来源只发生在检查/刷新命令中；有向图检查循环、重复身份和刷新顺序。文件移动后的重新定位必须核对内部身份和哈希，不能按同名文件自动替换。跨多文件批量写入需要单独设计失败恢复，不把逐目标原子提交说成全局事务。
- IO 只追加稳定 MessagePack 数字 Key 和显式节/版本迁移；旧文档生成空基准/依赖字段，并保留旧 M5 关系与冻结零件。新字段伪装成旧版本、缺少证据或引用指向错误资产时拒绝读取。先定精确 DTO/上限/迁移测试，再提升写出器版本；本计划不预留未实现的版本号。

### 实施顺序与验收

1. 先核对锁定的 `OcctSharp` / `OcctSharp.Native.win-x64` 包是否能对**原始 BRep** 提取平面/圆柱面/圆边解析数据并按精确证据定位。用独立 NuGet 消费探针证明；只有缺实际接口时才到相邻 `OcctSharp` 仓库补 C# 和原生封装、重打配对包并更新锁文件。
2. 接入基准选择、持久化与过期处理，覆盖旋转零件、STEP/XDE 实例、共享定义、多实例、删除/重算、旧文件迁移和误选拒绝。
3. 建立能处理闭环的刚体求解和局部自由度诊断，覆盖确定、欠约束、冗余、相互矛盾、奇异、断开连通图及多解；与 OCCT 干涉/实际位置复核。求解失败绝不发布部分位姿。
4. 扩展来源依赖检查与预演刷新，覆盖 A→B→C、环、移动/丢失、同名不同 ID、来源/本地同时变化、刷新中断、撤销、保存/重开和恢复。
5. 最后统一运行锁定还原、Release 零警告、全量/定向测试、独立 NuGet/原生 DLL 校验、真实 STEP 装配、桌面选择/拖动/取消/确认及四组发布版冒烟。仍须单列物理混合 DPI、RDP、长时间运行和新机器证据。

M10 的本机功能验收与未覆盖环境须在 [M10 装配](M10_ASSEMBLY.md)逐项列明；不把 M5 的有向求解算作闭环求解，也不把局部数值解宣称为全局唯一解。

## M11：二维工程图

目标是在文档中创建纸张/图纸、关联投影视图和可追踪尺寸。M7 的 HTML 审阅报告、M6 的世界坐标标注与截面都不是工程图。

| 工作面 | 计划数据与行为 | 验收要点 |
|---|---|---|
| 图纸结构 | `DrawingSheet` 持稳定 ID、纸张/方向/单位/比例；`DrawingView` 持零件或装配的精确来源、投影方向、中心/比例及父子视图关系 | 正、俯、右、轴测、局部/剖视中已支持的类型逐项声明；视图移位、比例和纸张设置可撤销并可保存重开 |
| 关联投影 | 从当前 BRep/XDE 及实例位姿生成 2D 可见/隐藏线，异步缓存按来源修订失效 | 不把屏幕截图当几何投影；上游改动可重算，失败保持旧已提交图纸并标明过期 |
| 工程尺寸 | `DrawingDimension` 以精确 3D/2D 引用、视图 ID、标注位置及样式表示长度、角度、半径/直径 | 值与真实几何和文档单位一致；拓扑失效需要重选，不自动贴到相邻边；打印和导出可读 |
| 交付 | 图框/标题栏、预览及 PDF/打印；交换格式能力明确标注 | 一页/多页、字体、线宽、比例、分页和无外部资源路径经过发布版视觉检查；HTML 报告继续独立存在 |

工程图数据应作为独立文档节演进，保留旧文件空图纸迁移与未知扩展节。先完成几何投影及尺寸引用的独立包能力核查；若 `OcctSharp` 缺隐线计算或解析投影接口，按 M10 相同的消费探针 → 上游补迁 → 配对包验证流程推进。阶段完成须有真实零件/装配的修改后关联刷新、往返、撤销、PDF 对照和发布版窗口验收。

M11 已按该契约交付的功能、未纳入的制图标准扩展，以及本机验证路径见 [M11 工程图](M11_TECHNICAL_DRAWINGS.md)。锁定 OcctSharp 包已有精确 HLR 与解析基准能力，本轮无需上游迁移。

## 交付验收：安装器与环境

这是一组产品门禁，**不因为 M11 代码完成而自动通过**。先选定安装器及运行时模式，形成锁定依赖清单和离线安装包，再在未安装开发 SDK/本地 NuGet 的干净 Windows x64 机器验证安装、首次启动、STEP/IGES/STL、保存恢复、卸载及残留。签名、公开发布和 CI 结果单独记录。

实际设备矩阵至少覆盖单屏/双屏不同 DPI 下浮动与停靠、RDP 断线重连、不同 GPU/驱动、数小时大模型交互与内存/句柄趋势；输入为哈希固定的 `11WiFi.step`、`MiniPC3.step` 和带装配关系的外部样本。每轮记录环境、崩溃/绑定日志、CPU/内存/句柄、文件与资产哈希及用户可见结果。真实磁盘满、断电、网络盘和跨厂商交换另列专项结果；无实机或外部证据时只能标记“未验收”。

M13 已完成自包含 x64 MSI、逐文件清单和本机安装目录/卸载复验，详见 [M13 安装器与环境](M13_INSTALLER_AND_ENVIRONMENT.md)。上述干净机器、物理混合 DPI/RDP、长时、签名及公开发布门禁仍按本计划单独取证。
