# H2-B3：有界多步历史诊断

本阶段把 `ITopologyHistoryResolver.TraceAsync` 扩展到 Box 语义面／边经局部与布尔特征组成的唯一后继链。典型路径为 Box → 圆角 → Cut → Fuse，也支持在不同段切换到不同输入参数。返回值只用于诊断，没有新增自动重绑定、跨特征持久引用或用生成面继续建模的入口。

继续使用本地 NuGet `8.0.1-preview.28.cadoryx.h2b2.2`，本阶段没有修改 OcctSharp 或增加原生 ABI。存储写出版本 0.4.5、八节 MessagePack 和 history v2 保持不变；诊断路径每次从当前不可变文档重新计算，不保存临时索引或原生句柄。

## 路径规划

`TopologyHistoryPaths.Plan` 在 Kernel.Abstractions 中，只读取特征依赖图。它从目标向上游遍历，以指定源特征为终点，检查目标的全部输入祖先；与目标无关的特征不参与规划。每个节点的路径数截断到 2，并记忆已完成节点，因此无需枚举指数数量的路径。

只有恰好一条路径才返回有序 `HistoryPathStep(Feature, SourceArgument)`。分支重合、直接与间接两条路径、经过不支持算法的另一条路径都不能靠挑选第一项消除歧义。两条路径即使可能收敛到同一几何也返回 `Ambiguous / HISTORY.MULTIPLE_PATHS`，CandidateCount 为 0，因为此时尚未计算拓扑候选数。

即使已发现多条路径，仍检查其余输入的缺失节点、重复依赖、跨零件引用和循环。图错误／遍历预算具有优先级；不会把残缺图当作已验证的多路径。没有源到目标的非空路径为 `Unsupported / HISTORY.NO_PATH`。

| 工作预算 | 上限 |
|---|---:|
| 唯一传播链 | 32 段 |
| 访问的不同特征 | 1,024 |
| 访问的输入边 | 4,096 |
| 遍历调用深度 | 128 |
| 累计新建原生诊断地图 | 256 |
| 新地图的声明拓扑槽位总数 | 1,000,000 |
| 已处理的历史关系总数 | 1,000,000 |

预算耗尽返回新增的 `LimitExceeded` 状态和具体诊断代码，不返回部分目标。地图与槽位预算在每段原生读取前检查，延续使用上一段结果的地图不重复计数。声明数量不符合真实 BRep 时仍返回 Stale。这些是诊断工作预算，不是整个应用的内存、资产字节、原生单次调用时间或大型模型性能保证。

## 逐段证据与索引

源仍必须是 Box 六面／十二边语义引用。解析先核对文档、输出体身份和 ExactRevision 策略，再在第一段源地图上确定唯一语义候选。后续段只允许已有局部或布尔历史，Transform、导入等无映射段不会被跳过。

每一段检查：

1. 配方类型、历史协议、输入顺序、结果修订及资产。
2. 当前局部／布尔适配器白名单。两种冻结 Preview.26 局部适配器继续验证；未知标签或错误类型的适配器拒绝。
3. 结果 BRep 重载后的指纹和拓扑数量。
4. **所有输入**的上游结果修订／资产、地图指纹／数量、全部面／边／顶点覆盖和源／结果种类。未被追踪的布尔操作数同样必须通过。
5. 当前源槽位的唯一保留／修改对应，且没有别的来源共享该目标。

上一段的结果 `RepairSnapshot` 直接成为下一段被追踪的输入地图；同一份精确资产的修订、指纹和数量还会再次与下一段证据比较。这样无需把索引转换成视口或邻接索引，也无需通过几何相似度猜测对应。其他输入逐个读取和释放；最多同时持有上一段、当前结果、当前侧输入三张诊断地图。

请求跨内核串行队列持有 `DocumentAssetLease`，包括已被后继消费的上游几何；成功、失败、取消和异常都释放地图／租约。Editor 的 `TopologyHistoryInspection` 保持文档与 StateId 检查，异步旧结果不得覆盖新文档状态。原生调用之间及关系遍历检查取消，单次原生调用内部不保证立即中断。

## 结果与失效

`HistoryResolution` 保留原有 Status、Target、CandidateCount、Diagnostic，并增加三个仅用于诊断的标量字段：

| 字段 | 含义 |
|---|---|
| PathLength | 已规划的唯一有界链长度；无法规划时为 0 |
| CompletedSteps | 已成功归约到唯一后继的段数 |
| StoppedAt | 首个停止的特征；全部成功时为空；图失败时为检测位置 |

三段链第二段拆分的结果是 Ambiguous、PathLength=3、CompletedSteps=1、StoppedAt=第二段特征、Target=null。不会把第一段的有效目标伪装为最终目标。

拆分／共享目标为 Ambiguous；原生明确删除为 Deleted；只有生成角色而没有唯一保留／修改关系为 Generated。它们都立即终止传播。缺少历史／覆盖或未验证适配器为 Unsupported；精确身份、指纹、数量失配为 Stale；源或依赖特征不存在为 Missing。非法历史协议返回 `HISTORY.INVALID_HISTORY`，不能进入索引访问。

上游重算沿现有依赖闭包重新评估并原子提交几何与证据。某段不再产生历史时清空该段旧记录，即使下游布尔仍有证据，也不能跨过空缺。精确撤销／重做恢复原来的不可变快照及证据；保存重开和异常退出恢复重新规划并验证当前 BRep，不复用旧诊断结果。

## 后续边界

下一小批 H2-C1 将提供用户可操作的历史诊断入口及持久化查询：保存源语义引用和目标特征 ID，重新打开时重新诊断，并在统一风格窗口中展示链与停止位置。它需要单独设计文件迁移、失效／删除行为和三语言 UI。

H2-C2 再设计真正跨特征的持久引用与显式重选／确认。诊断成功不能直接提升为建模授权；生成面／边、通用拓扑命名和自动重绑定仍需独立数据模型与内核证据验收。连续局部建模 T3、曲线区域 S3 以及混合 DPI/RDP／长期资源等专项门禁继续保留。
