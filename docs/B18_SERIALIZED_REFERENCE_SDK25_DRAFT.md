## 草稿实现

`BrepReferenceSnapshot.Capture(root, references)` 在调用者原生句柄被借用且存活时，通过实际 `IsSame` 成员查询记录来源地址；同坐标、独立复制及域外引用拒绝。一个 `BRepTools_ShapeSet` 写入实际根及组合位置，把根和所选成员转换为这个集合中的原生引用。

实际 BRep 带应用已有 `DBRep_DrawableShape` 文件头和 OCCT V3 图；引用表保存实际原生写引用、方向/类型和独立来源地址。原生 SHA256 同时绑定实际 BRep 与引用表，作用只是字节完整性，不能单独证明身份。使用 Windows 系统 bcrypt；它不计入 SDK 自带 62 原生 DLL 的数量。

解码在一个 ShapeSet 中同时恢复根与成员，逐条以原生成员查询取得解码地址，验证类型、方向和规范原生引用。原来源地址与解码地址分列，不用相等索引推导关系。图数量、字节、引用数量和令牌地址均有上限；旧 History 16 字节、copy32 和 domain48布局不变。

公开值报告与字节快照不持有原生指针，导出字节返回副本。原生 FeatureResult 使用已有注册/释放所有者，不新增全局句柄注册表；解码结果独立拥有一个根与其成员。每次 Restore 得到独立原生图，不能把另一次 Restore 或普通 BRep 读取的成员混入其中。

| 接口 | 当前草稿含义 |
| --- | --- |
| `Capture` | 实际在进程内捕获根/成员的原生所属与写引用；验证同图解码并复制数据。 |
| `CopyBrepBytes` / `CopyReferenceTable` | 导出独立数组，不暴露快照内部可变数据。 |
| `Open` | 检查绑定字节，实际解码并验证当前图的根/成员。原来源捕获仍未知。 |
| `Restore` | 在一个新图中恢复根与全部已验证原生成员，源/解码地址分别报告。 |
| `RestoreFromProvenNativeSource` | 只对实际在当前进程 Capture 的不可变快照成立；从文件 Open 的声明和哈希不能制造原来源证据。 |

`NativeSourceCaptureProven` 是实际 Capture 路径的独立状态，GUID 只作域标签。持久化 Open 的 `DeclaredSourceTopologyIndex` 仍是声明；即使重新计算完整性值，也不能据此取得原来源证明。`NativeDecodedMembershipProven` 只证明当前实际解码图的成员关系；完整内部路径和历史/跨作者组合标记保持 false。
