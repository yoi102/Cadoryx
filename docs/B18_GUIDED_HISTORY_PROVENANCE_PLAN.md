## 下一批实现顺序

1. 先增加有界、独立拥有的逐结果建模证明：实际SDK/原生版本、源作者/站点/通道ID和修订、实际转换公差/段数/阶数、原生报告的误差以及源/结果BRep哈希。只记录实际发生的准备与构建，不给棱柱分支虚构转换报告；没有原生误差报告的量明确为未知。
2. 把证明沿预览、准备提交、整笔C1重算、撤销重做和存储迁移传递。旧档案以显式“没有证明”读取；重存不能制造证据。取消/迟发/代次变化不得把证明附到错误结果；工作对象释放后证据自身仍可读且无原生指针。
3. 在隔离SDK源中核对pipe/loft真实原生Generated/Modified/首末截面关系，组合转换前后的来源身份。先提供不猜测的完整/缺失/多目标状态，不把一份转换历史当作整个管道/放样历史。主OcctSharp工作区与公开包保持独立；接入前两种真实原生配置和干净消费者分别验证。
4. 在应用中核对完整拓扑映射、源/结果指纹、资产/修订/上下文以及BRep保存往返身份。只有单一路径、唯一目标且原生历史完整时，才允许进入明确的生成面/边引用工作流；跨作者重算自动延续另须逐结果的原生对应证明。任一阶段没有证据即保持拒绝，不以源作者ID替代结果拓扑证明。
5. 补曲面结果的局部特征/工程图附着消费者和错误证据矩阵，再做生产选择、取消、确认、保存关闭重开窗口。源表达式、方向、通道、作者值以及独立体积公差继续核对。

第一部分的精度记录可先交付并改善导出说明；它本身不代表第三、四部分的历史延续完成。

下一批合并四项工作推进，按依赖顺序串行验证：

1. **独立原生历史快照。** 先在隔离SDK上公开实际输入域、最终输出域和Generated/Modified/Unmapped/首末截面的精确所属状态。维持旧History接口、原布局和已有断言；若现有接口无法提供复制对应，再增加小范围的独立拥有接口和必要版本标记。结果不完整也要返回明确原因，不把缺失状态涂成成功。
2. **实际BRep往返桥接。** 优先核对OCCT序列化形状表是否能给出从实际输出子形状到保存槽位，再到同一字节资产解码域的明确关系；这只是待验证方案。必须由原生序列化关系形成地址，不由坐标、同索引、同数量或字节哈希单独推定。如果原生机制不能提供该关系，保持保存后身份接续拒绝。
3. **应用逐阶段组合与迁移。** 准备、构建、复制、BooleanCut/Compound每一步绑定真实版本、来源快照、结果资产/修订和实际BRep字节。遗漏阶段、旧快照、部分覆盖、多路径、分裂/合并或往返证明缺失立即停止。当前观察记录分区仍只承担观察数据职责；原生身份证据独立版本化，旧文件保持没有证据。
4. **下游引用和生产窗口。** 先允许经过验证的当前结果明确选择，再验证局部特征和工程图附着消费者。跨作者C1重算的自动延续必须有新旧两结果之间独立的原生对应；当次作者ID、配方哈希及stage记录不能代替它。无证明继续要求明确重选，并测试取消、失效、保存关闭重开及一次撤销重做。

计划矩阵以现有八种真实曲面×方向×世界姿态×原始/C1共64场景作为来源，分别核对准备、pipe/loft、最终材料组合、释放后读取与实际BRep往返；缺失/多目标场景的正确结果可以是明确拒绝，不要求每种原生算法虚构完整映射。另覆盖错误计划/参数槽位/源类型、陈旧资产/修订、漏阶段、不同适配器、篡改持久化数据、兼容拆分、最终实体不包含历史目标及取消竞争。每个测试须保留真实几何、原公差和错误状态，预定矩阵不计入已通过数量。

原生真实Release和真实Debug、生成器及干净锁包消费者分别通过后才接入应用。应用Release/Debug、实际62原生加载、必要相关回归、完整回归和生产窗口继续分列；已结束的977两配置5565载荷和完整回执保持独立。
